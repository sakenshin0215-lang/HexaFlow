# HexaFlow 项目介绍

## 1. 项目定位

HexaFlow 是一个面向复杂网站（尤其是状态变化频繁、弹窗多、验证链路多）的 AI 网页自动化引擎。

核心目标不是“按死脚本跑”，而是：
1. 给目标与约束后自动推进任务。
2. 遇到异常时先自愈，再人工兜底。
3. 将成功路径沉淀为可复用轨迹。
4. 支持循环任务与长期稳定运行。

---

## 2. 核心工作流

### 2.1 动态执行（探索）
1. 读取目标（goal）与约束（TaskSpec）。
2. 采集当前 URL + 可交互 DOM。
3. AI 决策下一步动作（navigate/click/type/done）。
4. 执行动作并记录历史。

### 2.2 录制固化（示教）
1. 人工在页面操作。
2. 系统拦截并记录 click/type。
3. 可在录制时标记循环起止（`ls` / `le`）。
4. 生成 trace（JSON）。

### 2.3 回放执行（生产）
1. 读取 trace 并按步骤执行。
2. 每步执行前做页面守卫（Page Guard）。
3. 失败时按恢复链尝试修复。
4. 成功落盘状态，失败挂起并可恢复。

---

## 3. 浏览器策略

HexaFlow 支持两种启动方式：
1. 普通 Playwright 启动
2. CDP 连接真实 Chrome（推荐）

CDP 模式优势：
1. 复用你已有 Profile（登录态、扩展、钱包数据）。
2. 能做真实钱包连接与签名链路。
3. 引擎会复用现有 context，避免丢失扩展上下文。

---

## 4. 稳定性与恢复机制

### 4.1 页面守卫（Step Guard）
每个步骤可配置：
1. `guard_url_contains`
2. `on_mismatch_actions`
3. `guard_retry_limit`

作用：若当前不在规定页面，先回退修正，再执行主动作。

### 4.2 多层恢复链
回放步骤失败后按顺序：
1. 弹窗自愈（Healer）
2. 错页修复（reload/back/回跳）
3. 小流程回放修复
4. AI 修复器（改定位器/改动作/跳步/人工接管）
5. 挂起并等待人工恢复

### 4.3 人工接管
自动检测：
1. 登录/重新登录
2. 验证码/2FA/人机校验
3. 钱包解锁与签名确认

人工处理后按回车继续原任务。

---

## 5. 循环任务机制

### 5.1 循环定义
在录制 trace 时标记：
1. `loop_marker = start`
2. `loop_marker = end`

并用 `loop_name` 绑定同一循环段。

### 5.2 循环执行规则
在 `TaskSpec.loop_policy` 里配置：
1. `enabled`
2. `loop_name`
3. `iterations`
4. `max_iteration_retries`

关键约束：
1. 只有整轮循环步骤全部成功才计 1 次完成。
2. 某步失败则该轮重试，不计完成数。
3. 超过重试上限才挂起。

---

## 6. 运行态与可观测性

### 6.1 状态机
SQLite 持久化：
1. `run_id`
2. 当前步骤索引
3. 状态（running/suspended/failed/completed）
4. 事件时间线

### 6.2 报告
每次回放/恢复结束自动生成：
1. JSON 报告
2. Markdown 报告

包括：成功率、失败点、截图、恢复次数、时间线。

---

## 7. 适用场景

1. Web3 交互流程自动化
2. 多步骤后台操作自动化
3. 半自动+全自动混合运营流程
4. 需要“失败可恢复”的长期任务

---

## 8. 非目标

1. 本项目不是量化盈利策略引擎。
2. 不保证所有网站 100% 无人值守。
3. 对高风险操作建议保留人工确认环节。
